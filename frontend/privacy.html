🔒 Privacy

Banpani is built so people can be helped without being exposed. This page says exactly what we collect, why, and what never leaves the system.

The short version: no accounts, no logins, no names required. The public map shows needs and places — never people. Phone numbers are optional, never shown publicly, and never included in any download or API response.

What we collect

  • Reports: a location (pin on the map), what's needed, roughly how many people are affected, and any details you type.
  • An optional phone number — only if you choose to give one, so a relief volunteer can call back. The field is clearly marked optional.
  • Photos you choose to upload as evidence of flooding or relief work. Location metadata (GPS) is stripped from every photo in your browser before it is uploaded.
  • Convoy, drop-off, and NGO listings submitted by relief groups, including the group name they enter (which is public by design).
  • Verification votes (confirm / delivered / not real), limited to one per device.

Why we collect it

One purpose only: coordinating flood relief and rehabilitation — so stranded areas are found, effort isn't duplicated, and reports can be verified by the community. We do not use this data for anything else. We do not sell it, share it with advertisers, or profile anyone.

What is public and what is not

Public: the location and content of reports, flood polygons, convoy coverage, drop-off points, NGO listings, photos, and an activity feed where each participant appears only as an anonymous id.

Never public: phone numbers, names (we don't ask for them on reports), and IP addresses. Phone numbers are excluded from all bulk data, downloads, and API responses. A number can be revealed only one at a time, through a logged endpoint, when a volunteer actually needs to coordinate with that report — and every such access is recorded.

Consent

Everything you submit, you submit deliberately — there is no background collection, no tracking pixels, and no account to link things to. Giving a phone number is a choice, made at the point of reporting, for the stated purpose of being contacted about that need.

Open data

Because Banpani only works if everyone can see the same picture, the non-personal data — needs, flood extent, coverage, listings, photos — is open, dedicated to the public domain under Creative Commons CC0 1.0. It can be read by anyone through the public API and the 6-hourly situation report, and reused for any purpose. Personal identifiers are stripped from all of it by design.

Money never touches Banpani

Banpani never asks for, stores, or displays a bank account number, UPI ID, card, or any other way to collect money — not for us, not for anyone listed here. No donation or payment ever flows through this system. This is deliberate: it removes the single most common vector for fraud during a disaster, and it means there is no financial data to protect in the first place.

How long we keep it

Reports and coverage data are kept for the duration of the flood event and its rehabilitation phase, because "who was helped where" matters for accountability. Phone numbers are deleted once the event's relief coordination has wound down, and in any case within 3 months of submission.

Your rights

If you want a report, photo, or phone number removed — yours, or one concerning you — use the ✉ Contact form on the map. A maintainer will act on it. You don't need to prove anything elaborate; if a reasonable person would want it gone, it goes.

Where the data lives

The database runs on a single server operated by the maintainer, with the static site served through a content delivery network. The full source code is open, so every claim on this page can be checked against what the system actually does: github.com/parthajy/banpani.

Applicable law

Banpani is operated from India and handles personal data in line with the Digital Personal Data Protection Act, 2023, and the Information Technology Act, 2000. The same privacy-by-design principles (data minimisation, purpose limitation) align with the GDPR, so redeployments of this open-source code elsewhere start from a compliant baseline.

Changes

If this policy changes, the change will be visible in the public commit history of the repository — like everything else here, in the open.
